# Security reporting

Report vulnerabilities privately to the repository owner through GitHub's private
vulnerability-reporting channel when available. If it is unavailable, contact the
repository owner privately through an established channel before sharing exploit
details. Do not post credentials, application money data or exploitable findings
in public issues. No private-reporting setting or response SLA is implied here.

Include affected SDK/PHP/Laravel versions, a minimal synthetic reproducer, expected
and observed behavior, and impact on precision, identity, parsing or availability.
Use no real account data or external-service secrets.

There is no published supported release yet. Security fixes and supported release
lines will be recorded in the changelog and release notes. Never bypass Composer
security/platform checks to make an installation succeed.
